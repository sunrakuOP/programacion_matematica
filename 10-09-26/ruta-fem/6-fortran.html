PRG · 6.2 Instalar y compilar tu primer programa Fortran

Ya confirmado en esta Macgfortran (Homebrew GCC 16.2.0) ya está instalado en /opt/homebrew/bin/gfortran — el mismo compilador que se usó para verificar ambos proyectos de tu papá. La extensión "Modern Fortran" y el servidor fortls ya quedaron instalados en VS Code.

Fortran distingue dos formatos de archivo: .f90 es la sintaxis moderna (libre, la que vas a escribir siempre) y .f es la sintaxis vieja de Fortran 77 (fija por columnas — la que vas a ENCONTRAR cuando abras reference/f77/ del proyecto, código original de DELOS de los 80/90). No hace falta escribir .f nunca, solo reconocerlo al leerlo.

hola.f90fortran
program hola
  implicit none
  print *, "Hola, Nicolás"
end program hola
terminalbash
export PATH="/opt/homebrew/bin:$PATH"
gfortran -o hola hola.f90
./hola
# -> Hola, Nicolás

implicit none va SIEMPRE, sin excepción, al principio de cada programa/módulo/procedimiento: apaga una regla heredada de Fortran 66/77 donde una variable sin declarar tomaba tipo automáticamente según su primera letra (I-N enteros, el resto reales) — una trampa histórica de bugs silenciosos. El código real de tu papá seguro lo usa en todas partes; vos hacé lo mismo desde el primer programa.

El (8) en real(8) es el kind: cuántos bytes de precisión (8 = doble precisión, como double en C++; 4 sería como float). Siempre real(8) en código de ingeniería — la precisión simple no alcanza para acumular sumas de miles de elementos sin error visible.

variables.f90fortran
program variables
  implicit none
  real(8) :: base, altura, area
  base = 4.0d0
  altura = 2.5d0
  area = base * altura
  print *, "area = ", area
end program variables

PRG · 6.4 Control de flujo

if/else if/else/end if, do (un solo constructo para el for y el while de C++), select case (el switch de Fortran), exit/cycle (break/continue).

suma.f90fortran
integer :: i, suma
suma = 0
do i = 1, 10
  suma = suma + i
end do

Trampa clásica viniendo de C++do i = 1, 10 INCLUYE el 10 (intervalo cerrado), a diferencia de for(i=0; i<10; i++) en C++ que es medio-abierto. Un do i=1,n tiene exactamente n iteraciones, no n-1.

PRG · 6.5 Arrays — el superpoder de Fortran

Fortran nació para álgebra lineal y se nota: los arrays empiezan en índice 1 por defecto (no 0), una matriz se declara nativa real(8) :: K(3,3) sin librería, y hay operaciones de array completas: A = B + C suma elemento a elemento sin loop explícito, matmul(A,B) multiplica matrices, sum(A), transpose(A) — todo built-in, no una librería tipo Eigen.

La trampa real: orden de memoria column-major

C/C++ guarda un array 2D fila por fila (row-major); Fortran lo guarda columna por columna (column-major). No es un detalle cosmético: si recorrés un array en el orden equivocado, el programa sigue funcionando pero mucho más lento, porque salta por toda la memoria en vez de leerla secuencial (mala localidad de caché).

memoriatexto
Matriz 3x3, valores A(i,j):

  A(1,1) A(1,2) A(1,3)
  A(2,1) A(2,2) A(2,3)
  A(3,1) A(3,2) A(3,3)

C/C++ (row-major)   -> en memoria:
  A(1,1) A(1,2) A(1,3) A(2,1) A(2,2) A(2,3) A(3,1) A(3,2) A(3,3)
  bucle rápido: for(i) for(j) usar A[i][j]   // j varía más rápido

Fortran (column-major) -> en memoria:
  A(1,1) A(2,1) A(3,1) A(1,2) A(2,2) A(3,2) A(1,3) A(2,3) A(3,3)
  bucle rápido: do j; do i; usar A(i,j); end do; end do
                                            ! i varía más rápido -- el loop de ADENTRO
arrays.f90fortran
real(8) :: K(3,3), F(3), suma_K
K = 0.0d0
K(1,1) = 2.0d0;  K(2,2) = 2.0d0;  K(3,3) = 2.0d0
suma_K = sum(K)             ! sin loop -- built-in
F = matmul(K, [1.0d0, 1.0d0, 1.0d0])  ! multiplicación de matriz por vector, built-in

Arrays dinámicos: real(8), allocatable :: v(:) y después allocate(v(n)) — el equivalente a std::vector, pero vos controlás el crecimiento (siempre por doblado amortizado, per el tema 2.1, nunca reallocate por cada inserción).

PRG · 6.6 Subrutinas, funciones y módulos

function devuelve un valor (por su propio nombre o con result(...)); subroutine no devuelve nada por sí misma, se llama con call y modifica sus argumentos. intent(in)/intent(out)/intent(inout) documentan en la firma misma qué hace cada argumento — el compilador te avisa si lo violás, algo que C++ no fuerza.

module es la unidad de organización de Fortran — como un header+source de C++ combinados en un solo archivo. use nombre_modulo importa. Cada archivo de DELOS-3D ya sigue este patrón: un módulo por archivo .f90.

elemento_barra.f90fortran
module elemento_barra
  implicit none
contains
  subroutine rigidez_barra(E, A, L, k)
    real(8), intent(in)  :: E, A, L
    real(8), intent(out) :: k(2,2)
    real(8) :: EA_L
    EA_L = E * A / L
    k(1,1) =  EA_L;  k(1,2) = -EA_L
    k(2,1) = -EA_L;  k(2,2) =  EA_L
  end subroutine rigidez_barra
end module elemento_barra

program principal
  use elemento_barra
  implicit none
  real(8) :: k(2,2)
  call rigidez_barra(200.0d9, 0.001d0, 2.0d0, k)
  print *, k
end program principal

Este ejemplo (en gfortran/05-subrutinas-modulos/, ya compilado y probado) es el tema 6.1 (elemento barra) y el 3.4 (rigidez EA/L) en Fortran real — la misma fórmula que ya programaste en C++, traducida.

PRG · 6.7 Tipos derivados e interoperabilidad con C

type es el struct de Fortran:

nodo.f90fortran
type :: Nodo
  real(8) :: x, y, z
end type Nodo

type(Nodo) :: p1
p1%x = 1.0d0;  p1%y = 2.0d0;  p1%z = 0.0d0

Llamar código C desde Fortran: ISO_C_BINDING

Desde Fortran 2003, el módulo intrínseco iso_c_binding permite declarar una interfaz que llama directo a una función C compilada aparte (por ejemplo, en una DLL en Windows), con una interfaz bind(C) que garantiza compatibilidad binaria exacta con la convención de llamada de C:

interop.f90fortran
interface
  subroutine dibujar_triangulo(x1, y1, x2, y2, x3, y3) bind(C, name="dibujar_triangulo")
    use, intrinsic :: iso_c_binding
    real(c_double), value :: x1, y1, x2, y2, x3, y3
  end subroutine dibujar_triangulo
end interface

Esto le dice al compilador: "esta subrutina existe en otro archivo compilado en C, y así es su firma exacta". El núcleo numérico se queda en Fortran (rápido, lo que tu papá ya sabía) y una DLL en C hace de puente hacia gráficos de bajo nivel.

Nota de obra — la "DLL en C" que mencionaba tu papáHipótesis a confirmar cuando veas su código, no un hecho todavía: exactamente este patrón — Fortran + una DLL en C vía bind(C) — era la forma estándar de llegar a gráficos de bajo nivel (probablemente OpenGL, tema 5.4) antes de que existiera algo como Winteracter (tema 6.9), o para partes puntuales que Winteracter no cubría. Cuando tengan el código a la vista, buscá un bloque interface ... bind(C) ... end interface para confirmarlo.
