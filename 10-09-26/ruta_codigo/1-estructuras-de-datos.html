1.1 Memoria, punteros y referencias

Antes de cualquier estructura de datos hay que entender dónde viven los datos. Una variable normal vive en la pila (stack) — memoria automática, rápida, que se libera sola al salir de la función. Un puntero (int* p) guarda una dirección de memoria, no un valor — &x te da la dirección de x, *p ("desreferenciar") te da el valor guardado en esa dirección. Una referencia (int& r) es un alias de otra variable — más segura que un puntero (no puede ser nula, no se puede "reasignar" a otra cosa) pero menos flexible.

punteros.cppc++
void intercambiarPorPuntero(int* a, int* b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

void intercambiarPorReferencia(int& a, int& b) {
    int temp = a;
    a = b;
    b = temp;
}

int main() {
    int x = 5, y = 10;
    intercambiarPorPuntero(&x, &y);   // hay que pasar direcciones
    intercambiarPorReferencia(x, y);   // se pasa la variable misma

    int arr[5] = {10,20,30,40,50};
    int* p = arr;                     // un array "decae" a puntero a su primer elemento
    // arr[2] y *(p+2) son EXACTAMENTE la misma operacion
}
Salida real (compilado y corrido)
antes: x=5 y=10
despues de puntero: x=10 y=5
despues de referencia: x=5 y=10
arr[2] = 30, *(p+2) = 30

1.2 Arrays estáticos y dinámicos

Un array estático (int arr[5]) tiene tamaño fijo, conocido en tiempo de compilación. Un std::vector crece dinámicamente — pero NO reserva memoria nueva en cada push_back: duplica su capacidad cuando se queda sin espacio, y copia los elementos viejos a la memoria nueva. Esto es "crecimiento por doblado amortizado" — la razón exacta por la que agregar n elementos a un vector cuesta O(n) en total, no O(n²), aunque de vez en cuando una sola inserción sea cara (cuando toca duplicar).

arrays.cppc++
std::vector<int> v;
for (int i = 1; i <= 10; i++) {
    v.push_back(i * 10);
    // v.capacity() crece SOLO quando hace falta, nunca de a uno
}
Salida real — mirá cómo salta la capacidad, nunca sube de a uno
size=1 -> capacity crecio a 1
size=2 -> capacity crecio a 2
size=3 -> capacity crecio a 4
size=5 -> capacity crecio a 8
size=9 -> capacity crecio a 16
Nota de obraLa memoria del proyecto IFC-Bridge registra esta regla explícita: "amortised-doubling growth for every growable pool; never reallocate-per-insert" — exactamente este mecanismo, aplicado a los pools de entidades de un archivo IFC de cientos de MB.

1.5 Listas enlazadas (simple, circular, doble, centinela)

Un array guarda elementos en posiciones de memoria CONSECUTIVAS: acceso por índice O(1), pero insertar/eliminar en el medio es O(n) porque hay que correr todo lo que sigue. Una lista enlazada invierte el trade-off: cada nodo vive en cualquier parte de la memoria y apunta explícitamente al siguiente — acceder al elemento i es O(n) (no hay "saltar directo"), pero insertar/eliminar cuando ya tenés el puntero al lugar correcto es O(1) real, sin mover nada más.

El contrato TAD Lista (antes de cualquier implementación)

Un Tipo Abstracto de Datos define QUÉ operaciones existen y QUÉ hacen, sin decir CÓMO están armadas por dentro. El TAD Lista exige, como mínimo: crear() (lista vacía), esVacia(), insertar(valor, posición), eliminar(valor o posición), buscar(valor), tamaño() y recorrer(). Todo lo que sigue — simple, circular, doble, con centinela — implementa EXACTAMENTE esa misma interfaz. Lo único que cambia es el costo de cada operación según cómo esté conectada la memoria por dentro. Esa distinción (interfaz vs. implementación) es la que separa "sé hacer una lista" de "entender las listas" — y es la pregunta que un examen formal te va a hacer: no "escribí insertar", sino "¿por qué esta operación cuesta lo que cuesta en ESTA implementación del TAD?".

1.5.1 — Lista simple

Cada nodo apunta solo al siguiente; el último apunta a nullptr. Insertar al frente es O(1) siempre. Insertar al final es O(n) (hay que recorrer hasta encontrar el último) salvo que se mantenga un puntero cola aparte — eso lo baja a O(1), al costo de tener que mantenerlo sincronizado en cada operación que toque el final (si te olvidás de actualizarlo en un solo lugar, queda apuntando a un nodo viejo y todo lo que insertes "al final" después se pierde).

lista_simple.cppc++
struct Nodo {
    int valor;
    Nodo* siguiente;
};

Nodo* insertarAlInicio(Nodo* cabeza, int valor) {
    return new Nodo{valor, cabeza};   // O(1): nunca hay que correr nada
}

Nodo* eliminarPorValor(int valorComparar, Nodo* cabeza) {
    Nodo* anterior = nullptr;
    Nodo* auxiliar = cabeza;
    while (auxiliar != nullptr) {
        Nodo* siguienteReal = auxiliar->siguiente;   // guardar ANTES de delete
        if (auxiliar->valor == valorComparar) {
            if (anterior == nullptr) cabeza = auxiliar->siguiente;  // borra la cabeza
            else anterior->siguiente = auxiliar->siguiente;
            delete auxiliar;
        } else {
            anterior = auxiliar;
        }
        auxiliar = siguienteReal;
    }
    return cabeza;
}

1.5.2 — Lista circular

Igual que la simple, pero el último nodo no apunta a nullptr — apunta de vuelta a la cabeza, cerrando el círculo. Eso agrega una complicación real que la lista simple no tiene: para insertar o eliminar la cabeza, hay que encontrar primero QUIÉN cierra el círculo (el nodo cuyo siguiente es la cabeza vieja) para reconectarlo al nodo nuevo. Encontrar ese nodo es O(n) salvo que mantengas un puntero cola (igual que en la simple, pero acá cola->siguiente siempre es la cabeza, así que insertar al final con cola es O(1) sin tener que buscar el cierre).

lista_circular.cppc++
Nodo* insertarAlInicioCircular(Nodo* cabeza, int valor) {
    if (cabeza == nullptr) {
        Nodo* nuevo = new Nodo{valor, nullptr};
        nuevo->siguiente = nuevo;           // se apunta a si mismo
        return nuevo;
    }
    Nodo* cierre = cabeza;
    while (cierre->siguiente != cabeza) cierre = cierre->siguiente;  // encontrar quien cierra
    Nodo* nuevo = new Nodo{valor, cabeza};
    cierre->siguiente = nuevo;               // el cierre ahora apunta al nuevo
    return nuevo;                            // el nuevo es la nueva cabeza
}

con cola (O(1), sin recorrer para cerrar): 8, 3, 20

1.5.3 — Lista doblemente enlazada

Cada nodo tiene DOS punteros: siguiente Y anterior. Eso resuelve el problema estructural de simples/circulares: para eliminar un nodo necesitabas el puntero al anterior, y conseguirlo significaba recorrer desde la cabeza aunque ya tuvieras el nodo en la mano. Con anterior, cada nodo conoce a su vecino de atrás directamente — el costo es memoria extra (un puntero más por nodo) y el doble de punteros para mantener sincronizados en cada operación.

lista_doble.cppc++
struct Nodo {
    int valor;
    Nodo* siguiente;
    Nodo* anterior;
};

Nodo* insertarAlInicio(int valor, Nodo* cabeza) {
    Nodo* nuevo = new Nodo{valor, cabeza, nullptr};
    if (cabeza != nullptr) cabeza->anterior = nuevo;   // el viejo primero mira hacia atras al nuevo
    return nuevo;
}

// bug clasico (slide de Gonzalo): comparar con == para encontrar, nunca asignar con =;
// y guardar el siguiente ANTES del delete, nunca usar el puntero despues de borrarlo
Nodo* eliminarPorValor(Nodo* cabeza, int valorBuscado) {
    Nodo* aux = cabeza;
    while (aux != nullptr) {
        if (aux->valor == valorBuscado) {
            Nodo* siguienteReal = aux->siguiente;        // guardado ANTES del delete
            if (aux->anterior != nullptr) aux->anterior->siguiente = aux->siguiente;
            else cabeza = aux->siguiente;                 // era la cabeza
            if (aux->siguiente != nullptr) aux->siguiente->anterior = aux->anterior;
            delete aux;
            aux = siguienteReal;
        } else {
            aux = aux->siguiente;
        }
    }
    return cabeza;
}

1.5.4 — Lista con centinela (nodo cabecera)

Una lista con centinela agrega un nodo "falso" que SIEMPRE existe, incluso en una lista vacía — cabeza nunca es nullptr, apunta al centinela, y el primer nodo real es centinela->siguiente. La ganancia: todas las ramas especiales que escribiste para "¿es la cabeza?" o "¿la lista está vacía?" desaparecen, porque insertar/eliminar en la posición 0 deja de ser un caso distinto — siempre hay un nodo antes de donde estás parado. El costo es un nodo de memoria que no representa un dato real y hay que recordar ignorar en los recorridos/impresión. Todavía no la viste en clase — si Gonzalo la da, este es el lugar para el código real cuando llegue.

1.6 Pilas y colas (TAD + arreglo circular + ejercicios)

Una pila (stack) es LIFO — último en entrar, primero en salir. El TAD exige push, pop, top, esVacia. Una cola (queue) es FIFO — primero en entrar, primero en salir. El TAD exige encolar, desencolar, front, esVacia. Los dos son la base de DFS y BFS (Fase 2): DFS usa una pila (o recursión, que ES una pila implícita), BFS usa una cola.

pilas_colas.cppc++
std::stack<int> pila;
pila.push(1); pila.push(2); pila.push(3);
// pila.top() da 3, pila.pop() lo saca

std::queue<int> cola;
cola.push(1); cola.push(2); cola.push(3);
// cola.front() da 1, cola.pop() lo saca
Salida real
pila (LIFO): 3 2 1
cola (FIFO): 1 2 3
Nota de obraComparalo con la bfs.f90 del tema 2.3 de ruta-fem: los arrays cola/inicio_cola/fin_cola de ese código Fortran son, literalmente, una cola implementada a mano con un array — porque Fortran no tiene std::queue nativo. El tema de abajo (arreglo circular) es exactamente ese mecanismo, explicado a fondo.

Implementación con arreglo circular (la versión de verdad, no la STL)

Implementar una cola con un array normal tiene un problema: si desencolar mueve el "inicio" hacia adelante sin mover todo el contenido, las posiciones de atrás quedan desperdiciadas para siempre. La solución es que los índices inicio y fin "envuelvan" (wrap around) con el operador módulo — cuando llegan al final del array, el % capacidad los manda de vuelta a la posición 0, reciclando el espacio libre. Es la misma idea que una lista circular (tema 1.5.2), pero sobre memoria contigua en vez de punteros.

cola_circular.cppc++
struct ColaCircular {
    int* datos;
    int capacidad, inicio = 0, fin = 0, cantidad = 0;

    bool esVacia() const { return cantidad == 0; }
    bool esLlena() const { return cantidad == capacidad; }

    bool encolar(int valor) {
        if (esLlena()) return false;
        datos[fin] = valor;
        fin = (fin + 1) % capacidad;   // el modulo es lo que "envuelve" el indice
        cantidad++;
        return true;
    }
    bool desencolar(int& valor) {
        if (esVacia()) return false;
        valor = datos[inicio];
        inicio = (inicio + 1) % capacidad;
        cantidad--;
        return true;
    }
};

Los 4 ejercicios clásicos (Gonzalo)

Paréntesis balanceados: recorrer el string, empujar cada apertura a una pila, y al encontrar un cierre, verificar que el tope de la pila sea la apertura correspondiente (si la pila está vacía o no coincide, no está balanceado). Al final, la pila debe quedar vacía.

Notación postfija (ej. 3 4 + = 7): recorrer token por token; si es un número, a la pila; si es un operador, sacar los DOS últimos números de la pila, aplicar el operador, y el resultado vuelve a la pila. El último valor que queda en la pila es la respuesta — ningún paréntesis necesario, por eso las calculadoras viejas (HP) usaban esta notación.

Papa caliente (Josephus con cola circular): todos en una cola, rotás k-1 veces (sacar del frente, meter atrás), y al que queda al frente en la vuelta k se elimina. Se repite hasta que queda uno solo.

Cola con dos pilas: encolar siempre va a la pila "entrada". desencolar: si la pila "salida" está vacía, volcás TODA la "entrada" en la "salida" (eso invierte el orden una vez), y sacás de "salida". El truco: cada elemento se invierte exactamente una vez en toda su vida, así que el costo amortizado sigue siendo O(1) por operación, aunque un volcado puntual sea O(n).

ejercicios_pilas_colas.cppc++
int evaluarPostfija(const std::string& expr) {
    std::stack<int> pila;
    std::istringstream iss(expr);
    std::string token;
    while (iss >> token) {
        if (token == "+" || token == "-" || token == "*" || token == "/") {
            int b = pila.top(); pila.pop();
            int a = pila.top(); pila.pop();
            if (token == "+") pila.push(a + b);
            else if (token == "-") pila.push(a - b);
            else if (token == "*") pila.push(a * b);
            else pila.push(a / b);
        } else {
            pila.push(std::stoi(token));
        }
    }
    return pila.top();
}

1.7 Búsqueda: lineal y binaria

Búsqueda lineal: revisar uno por uno, O(n). Búsqueda binaria: SOLO funciona en datos ORDENADOS — comparar contra el elemento del medio, descartar la mitad, repetir: O(log n). Es el mismo principio del árbol binario de búsqueda (Fase 2), aplicado a un array plano en vez de una estructura enlazada.

busqueda.cppc++
int busquedaBinaria(const std::vector<int>& v, int objetivo) {
    int izq = 0, der = (int)v.size() - 1;
    while (izq <= der) {
        int medio = izq + (der - izq) / 2;
        if (v[medio] == objetivo) return medio;
        else if (v[medio] < objetivo) izq = medio + 1;
        else der = medio - 1;
    }
    return -1;
}
Salida real — buscar en {1,3,5,7,9,11,13,15}
buscar 7 -> indice 3
buscar 4 -> indice -1 (no existe)

1.8 Ordenamiento

Ordenamiento por inserción (O(n²)): tomar cada elemento y correrlo hacia atrás hasta su posición correcta entre los ya ordenados — simple, bueno para arrays casi ordenados o muy chicos, malo para arrays grandes.

insercion.cppc++
void ordenamientoPorInsercion(std::vector<int>& v) {
    for (size_t i = 1; i < v.size(); i++) {
        int clave = v[i];
        int j = (int)i - 1;
        while (j >= 0 && v[j] > clave) {
            v[j+1] = v[j];
            j--;
        }
        v[j+1] = clave;
    }
}
Salida real — ordenar {5,2,8,1,9,3}
insercion: 1 2 3 5 8 9
std::sort: 1 2 3 5 8 9

Para arrays grandes, tres familias O(n log n) (la fila buena de la tabla de complejidad):

  • Mergesort: divide el array a la mitad recursivamente, ordena cada mitad, mezcla — estable, predecible, siempre O(n log n).
  • Quicksort: elige un "pivote", particiona en menores/mayores, recursión — en promedio muy rápido, en el peor caso O(n²) (poco común con buena elección de pivote).
  • Heapsort: construye un heap (Fase 2, tema 2.3) y va extrayendo el máximo — O(n log n) garantizado SIEMPRE, sin caso peor malo, y sin memoria extra (a diferencia de mergesort).
Nota de obradelos_topology.f90 (Fase 2 de DELOS-3D) usa exactamente heapsort para encontrar conectividad entre triángulos — la elección no es arbitraria: heapsort garantiza O(n log n) siempre, sin el riesgo de caso-peor de quicksort, que importa cuando el input es una malla real con estructura geométrica (no aleatoria) que podría, en teoría, disparar el peor caso de un quicksort mal elegido.
Autoevaluación¿Por qué DELOS-3D preferiría heapsort (garantía siempre O(n log n)) sobre quicksort (rápido en promedio, pero con un peor caso O(n²) real) para procesar una malla?

1.9 Tablas hash (std::unordered_map)

Ya viste 3 formas de acceder a datos: por índice (array/vector, O(1), pero solo con posiciones 0,1,2...), por recorrido (lista enlazada, O(n), buscando valor por valor), y por búsqueda binaria (O(log n), pero exige tener todo ordenado). Una tabla hash es una cuarta forma: acceso por una clave arbitraria (un número de ID, un texto, lo que sea) en tiempo O(1) promedio — ni hace falta que esté ordenado, ni que la clave sea un índice secuencial.

Cómo funciona, por dentro: una función de hash convierte la clave (por ejemplo, el entero 4521) en un número, que se usa como índice dentro de un array interno — así, buscar por clave termina siendo, en el fondo, acceso por índice, disfrazado. Cuando dos claves distintas caen en la misma posición (una "colisión"), cada posición del array interno guarda una lista enlazada chiquita con las claves que colisionaron ahí — el mismo NodoLista del tema 1.5, trabajando como pieza interna de una estructura más grande, igual que Matriz<T> lo fue de ElementoBarra.

hash1.cppc++
struct Entidad {
    int idExterno;
    std::string tipo;
};

std::vector<Entidad> entidades = {{4521, "IFCWALL"}, {103, "IFCBEAM"}, {88, "IFCCOLUMN"}};

std::unordered_map<int, int> idAIndice;   // idExterno -> posicion real en el vector
for (int i = 0; i < (int)entidades.size(); i++) {
    idAIndice[entidades[i].idExterno] = i;
}

int buscado = 103;
auto it = idAIndice.find(buscado);
if (it != idAIndice.end()) {
    int idx = it->second;
    // entidades[idx] -- acceso directo, sin recorrer nada
}

Entidad #103 encontrada en indice 1 (tipo IFCBEAM)

1.10 Complejidad formal: sumatorias y demostraciones

El tema 1.3 (Big-O) te da la intuición. Esto es la versión formal que un examen te puede pedir demostrar, no solo intuir.

Ciclos dependientes: la sumatoria resuelve el conteo

Cuando el límite del ciclo interno depende de la variable del externo (for j = 0; j < i, no j < n), el número de iteraciones NO es n * n — hay que sumar cuántas veces corre el interno para cada valor del externo: T(n) = Σ(i=0 hasta n-1) i = 0+1+2+...+(n-1) = n(n-1)/2. Esa es la fórmula de Gauss, y el resultado sigue siendo O(n²) (el término dominante de un polinomio de grado 2), aunque el conteo exacto sea la mitad de un ciclo cuadrado completo.

complejidad_formal.cppc++
long contarTriangular(int n) {
    long contador = 0;
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < i; j++) {   // OJO: j < i, no j < n
            contador++;
        }
    }
    return contador;
}
Salida real (compilado y corrido) — contador real vs. fórmula n(n-1)/2
n=5   -> contador=10,   formula=10
n=10  -> contador=45,   formula=45
n=100 -> contador=4950, formula=4950

Notación O: la demostración formal (no "se ve O(n²)")

La definición real: f(n) = O(g(n)) si existen constantes c > 0 y n₀ tales que f(n) ≤ c·g(n) para todo n ≥ n₀. Ejemplo demostrado: f(n) = 3n² + 5n + 2 es O(n²). Para n ≥ 1: 5n ≤ 5n² y 2 ≤ 2n², entonces f(n) ≤ 3n² + 5n² + 2n² = 10n². Con c = 10 y n₀ = 1, la desigualdad se cumple siempre — queda demostrado, no "parece".

while: el conteo sale de cómo cambia la variable de control

En un for, el número de iteraciones suele ser obvio por el límite. En un while, hay que mirar CÓMO cambia la condición para saber cuántas vueltas da. Si n se divide a la mitad cada vuelta (n = n / 2), después de k vueltas queda n / 2^k — el loop termina cuando eso llega a 1, es decir k = log₂(n). Por eso búsqueda binaria (tema 1.7) es O(log n): cada vuelta divide el espacio de búsqueda a la mitad.

Salida real (compilado y corrido) — iteraciones de un while que divide a la mitad, vs. log₂(n)
n=8        -> iteraciones=3   (log2(8)=3)
n=16       -> iteraciones=4   (log2(16)=4)
n=100      -> iteraciones=6   (log2(100)=6.64, redondeado)
n=1000000  -> iteraciones=19  (log2(1000000)=19.9, redondeado)

1.11 STL y lambdas

Hasta ahora escribiste todo a mano (struct + punteros crudos) para entender el mecanismo interno. La STL (std::vector, std::stack, std::queue, std::list) es la misma interfaz, ya optimizada y probada — se usa en código real una vez que el mecanismo ya se entiende, nunca como atajo para saltarse el aprendizaje. Una lambda ([](...){...}) es una función anónima que se pasa como argumento — la forma moderna de decirle a un algoritmo "ordená con ESTE criterio" sin escribir una función aparte con nombre.

stl_algoritmos.cppc++
struct Estudiante { std::string nombre; int semestre; };
std::vector<Estudiante> est = {{"Ana",3},{"Beto",7},{"Caro",1},{"Dani",7},{"Eva",5}};

// sort con criterio propio: la lambda dice "quien va primero"
std::sort(est.begin(), est.end(), [](const Estudiante& a, const Estudiante& b) {
    return a.semestre < b.semestre;
});

// lower_bound: primer elemento >= objetivo, en O(log n), SOLO si ya esta ordenado
auto it = std::lower_bound(semestres.begin(), semestres.end(), 5);

// accumulate: reduce todo el rango a un solo valor (aca, una suma)
int suma = std::accumulate(semestres.begin(), semestres.end(), 0);

// unique: compacta repetidos CONSECUTIVOS al final del rango (hay que erase() lo que sobra)
