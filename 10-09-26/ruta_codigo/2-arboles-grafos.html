2.1 Árboles binarios de búsqueda

Ya viste la teoría (qué es un BST, por qué es O(log n)) en Ruta al FEM, tema 2.2. Acá va la implementación completa: insertar, buscar, y los tres recorridos clásicos.

bst.cppc++
struct NodoBST {
    int valor;
    std::unique_ptr<NodoBST> izq, der;
    NodoBST(int v) : valor(v) {}
};

void insertar(std::unique_ptr<NodoBST>& raiz, int valor) {
    if (!raiz) { raiz = std::make_unique<NodoBST>(valor); return; }
    if (valor < raiz->valor) insertar(raiz->izq, valor);
    else insertar(raiz->der, valor);
}

bool buscar(NodoBST* raiz, int valor) {
    if (!raiz) return false;
    if (raiz->valor == valor) return true;
    return valor < raiz->valor ? buscar(raiz->izq.get(), valor) : buscar(raiz->der.get(), valor);
}

void inorder(NodoBST* raiz) {   // izquierda, nodo, derecha
    if (!raiz) return;
    inorder(raiz->izq.get());
    // visitar raiz->valor
    inorder(raiz->der.get());
}
Salida real — insertar 50,30,70,10,40,60,80
inorder (debe salir ordenado): 10 30 40 50 60 70 80
buscar 40: encontrado
buscar 45: no encontrado

El recorrido inorder de un BST SIEMPRE da los valores en orden ascendente — no es casualidad, es la propiedad estructural del árbol (todo lo menor a la izquierda, mayor a la derecha) haciéndose visible. Los otros dos recorridos: preorder (nodo, izquierda, derecha — útil para copiar/serializar un árbol) y postorder (izquierda, derecha, nodo — útil para liberar memoria de abajo hacia arriba, o para evaluar expresiones).

2.2 Árboles balanceados (AVL)

El problema real del tema 2.1: insertar valores YA ordenados (30, 20, 10...) degenera el BST en una lista enlazada — O(n), no O(log n). Un árbol AVL corrige esto automáticamente: después de cada inserción, si el "factor de balance" (altura del subárbol izquierdo menos la del derecho) se pasa de 1, aplica una rotación que reacomoda los nodos sin romper el orden.

avl.cppc++
NodoAVL* rotarDerecha(NodoAVL* y) {
    NodoAVL* x = y->izq;
    NodoAVL* T2 = x->der;
    x->der = y;               // x sube, se convierte en la nueva raiz local
    y->izq = T2;               // y baja, hereda el subarbol que x le "presta"
    y->altura = std::max(altura(y->izq), altura(y->der)) + 1;
    x->altura = std::max(altura(x->izq), altura(x->der)) + 1;
    return x;
}

// dentro de insertar(), despues de insertar recursivamente:
int balance = factorBalance(nodo);
if (balance > 1 && valor < nodo->izq->valor)   // caso izquierda-izquierda
    return rotarDerecha(nodo);
Salida real — insertando 30, 20, 10 en ese orden (el caso que degrada un BST normal)
insertando 30, 20, 10 en ese orden:
  -> desbalance detectado en nodo 30, rotando a la derecha
raiz final: 20 (deberia ser 20, no 30 -- el arbol se autobalanceo)
altura del arbol: 2 (un BST comun sin balancear tendria altura 3)

Con el mismo input que arruinaba un BST común, el AVL termina con 20 como raíz y 10/30 como sus dos hijos — altura 2, no 3. Existen 4 casos de desbalance (izquierda-izquierda, derecha-derecha, izquierda-derecha, derecha-izquierda), cada uno con su propia combinación de rotaciones — el código completo (en el archivo fuente) los cubre todos, pero el mecanismo de fondo es el mismo rotarDerecha/rotarIzquierda de arriba.

2.3 Heaps y colas de prioridad

Un heap es un árbol binario (guardado en un array plano, sin punteros) con una sola propiedad: cada nodo es mayor (max-heap) o menor (min-heap) que sus hijos. No está totalmente ordenado — solo garantiza que la raíz es siempre el máximo (o mínimo). Eso alcanza para responder "dame el más grande" en O(1) y "sacá el más grande y reacomodá" en O(log n) — mucho más barato que mantener un array totalmente ordenado.

heap.cppc++
std::priority_queue<int> maxHeap;
for (int v : {5,2,8,1,9,3}) maxHeap.push(v);
// maxHeap.top() siempre da el mayor actual, sin buscarlo

// heapsort real, con las funciones de heap de la STL:
std::vector<int> v = {5,2,8,1,9,3};
std::make_heap(v.begin(), v.end());   // O(n): construye el heap
std::sort_heap(v.begin(), v.end());   // O(n log n): extrae uno por uno
Salida real
extrayendo del heap (mayor a menor): 9 8 5 3 2 1
heapsort: 1 2 3 5 8 9
Nota de obraUna cola de prioridad es exactamente lo que necesita un algoritmo greedy ordenado por calidad — como el emparejado de triángulos de DELOS-3D (Fase 6 del proyecto, ya visto en Ruta al FEM, tema 2.4): en vez de ordenar TODOS los candidatos de una (costoso si aparecen nuevos candidatos sobre la marcha), un heap te da siempre "el mejor candidato restante" en O(log n) por operación.
Autoevaluación¿Por qué un heap es más barato de mantener que un array siempre-ordenado, si en ambos casos "sacar el máximo" es O(1) o casi?

2.4 Árboles espaciales: quad-tree

Ya lo viste conceptualmente en Ruta al FEM, tema 2.2. Acá, la implementación: un quad-tree divide el plano en 4 cuadrantes recursivamente, cada nodo guarda hasta capacidad puntos antes de subdividirse. La clave de la eficiencia está en consultar(): si el rectángulo de búsqueda NO toca la región de un nodo, se descarta esa región ENTERA sin mirar ni uno de sus puntos.

quadtree.cppc++
void consultar(const Rectangulo& rango, std::vector<Punto>& encontrados) {
    if (!limite.interseca(rango)) return;  // <- descarta la region ENTERA acá
    for (auto& p : puntos) if (rango.contiene(p)) encontrados.push_back(p);
    if (dividido) {
        ne->consultar(rango, encontrados);  no->consultar(rango, encontrados);
        se->consultar(rango, encontrados);  so->consultar(rango, encontrados);
    }
}
Salida real — 100 puntos en una grilla 10×10, buscar cerca de (15,15)
puntos totales en el arbol: 100
puntos encontrados cerca de (15,15): 4
nodos del quadtree visitados para responder: 13 (mucho menos que 100)

13 nodos visitados en vez de revisar los 100 puntos uno por uno — con una malla de decenas de miles de nodos reales, esa diferencia es la que separa un mallador utilizable de uno que tarda minutos en cada consulta "¿hay un punto cerca de acá?". En 3D, la misma idea con 8 subdivisiones en vez de 4 es un octree.

2.5 Grafos: representación y recorridos

Versión en C++ del bfs.f90 de Ruta al FEM, tema 2.3 — ahora con lista de adyacencia real (vector<vector<int>>) y, además de BFS, su contraparte DFS con una pila explícita.

grafo.cppc++
std::vector<std::vector<int>> adj(n);  // lista de adyacencia

// BFS: cola
std::queue<int> cola;  cola.push(0);  visitado[0]=true;
while (!cola.empty()) {
    int actual = cola.front(); cola.pop();
    for (int vecino : adj[actual])
        if (!visitado[vecino]) { visitado[vecino]=true; cola.push(vecino); }
}

// DFS: pila (misma estructura, cambia SOLO la cola por una pila)
std::stack<int> pila;  pila.push(0);
while (!pila.empty()) {
    int actual = pila.top(); pila.pop();
    if (visitado[actual]) continue;
    visitado[actual] = true;
    for (int vecino : adj[actual]) if (!visitado[vecino]) pila.push(vecino);
}
Salida real — mismo grafo de 6 nodos
BFS desde 0: 0 1 2 3 4 5
DFS desde 0: 0 2 4 5 3 1

BFS y DFS visitan los mismos nodos pero en orden distinto — y fijate que la ÚNICA diferencia real en el código es cambiar queue por stack. Esa simetría (misma estructura de algoritmo, diferente estructura de datos subyacente) es una de las cosas más elegantes de este tema.

2.6 Caminos mínimos: Dijkstra

BFS encuentra el camino más corto en NÚMERO DE ARISTAS (todas "pesan" lo mismo). Cuando cada arista tiene un costo distinto (distancia, tiempo, rigidez), hace falta Dijkstra: una cola de prioridad (tema 2.3) que siempre expande primero el nodo con menor distancia acumulada conocida hasta el momento.

dijkstra.cppc++
std::vector<int> dist(n, INT_MAX);
dist[0] = 0;
std::priority_queue<std::pair<int,int>, std::vector<std::pair<int,int>>, std::greater<>> pq;
pq.push({0,0});  // (distancia, nodo) -- min-heap por distancia
while (!pq.empty()) {
    auto [d, u] = pq.top(); pq.pop();
    if (d > dist[u]) continue;   // ya encontramos algo mejor, ignorar
    for (auto [v, peso] : adj[u])
        if (dist[u] + peso < dist[v]) { dist[v] = dist[u] + peso; pq.push({dist[v], v}); }
}
Salida real
distancias minimas desde el nodo 0:
  a 0: 0
  a 1: 3   (via 0->2->1, cuesta 1+2=3, mejor que el directo 0->1 que cuesta 4)
  a 2: 1
  a 3: 4
  a 4: 7

No es un algoritmo que uses directo en DELOS-3D o IFC-Bridge (ninguno de los dos resuelve caminos con peso) — pero es una pieza fundacional de la caja de herramientas de grafos, y aparece en optimización de mallas, ruteo de cableado en BIM, y análisis de redes en general.

2.7 Union-Find (conjuntos disjuntos)

La estructura de datos hecha a medida para UNA pregunta: "¿estos dos elementos están en el mismo grupo conectado?" — sin tener que recorrer el grafo completo cada vez. Cada elemento apunta a un "padre"; el elemento cuyo padre es él mismo es la raíz (el "representante") de su grupo. Dos optimizaciones la hacen casi O(1) por operación: compresión de camino (al buscar la raíz, aplanar el camino para la próxima vez) y unión por rango (el árbol más chico cuelga del más grande, nunca al revés).

union_find.cppc++
int encontrar(int x) {
    if (padre[x] != x) padre[x] = encontrar(padre[x]);  // compresion de camino
    return padre[x];
}
void unir(int a, int b) {
    int ra = encontrar(a), rb = encontrar(b);
    if (ra == rb) return;
    if (rango[ra] < rango[rb]) std::swap(ra, rb);   // union por rango
    padre[rb] = ra;
    if (rango[ra] == rango[rb]) rango[ra]++;
}
Salida real — 8 "triángulos", conectados en 3 grupos
componentes conectadas:
  triangulo 0 -> raiz de su grupo: 0     triangulo 4 -> raiz de su grupo: 3
  triangulo 1 -> raiz de su grupo: 0     triangulo 5 -> raiz de su grupo: 5
  triangulo 2 -> raiz de su grupo: 0     triangulo 6 -> raiz de su grupo: 5
  triangulo 3 -> raiz de su grupo: 3     triangulo 7 -> raiz de su grupo: 5

0 y 5 estan en el mismo grupo? no
Nota de obraEsto es, con nombre y apellido, el algoritmo estándar para lo que la Fase 2 de DELOS-3D llama "connected components" (componentes conectadas) — agrupar triángulos que están unidos entre sí, separándolos de otros grupos de triángulos que no tocan al primero (por ejemplo, dos regiones separadas de una misma malla). El ejemplo de arriba usa unir() una vez por cada arista compartida entre triángulos — exactamente el patrón que usarías para replicar esa fase del proyecto en C++.

2.8 Árboles de expresión

Conecta directo con la notación postfija del tema 1.6 (pilas): en vez de solo EVALUAR la expresión con una pila de números, se construye un árbol real con una pila de nodos — cada operador es un nodo interno con dos hijos (sus operandos), cada número es una hoja. El mismo algoritmo de evaluación postfija, pero acumulando estructura en vez de solo el resultado.

arbol_expresion.cppc++
struct NodoExpr { std::string valor; NodoExpr* izq; NodoExpr* der; };

NodoExpr* construirDesdePostfija(const std::string& expr) {
    std::stack<NodoExpr*> pila;
    std::istringstream iss(expr);
    std::string token;
    while (iss >> token) {
        NodoExpr* nodo = new NodoExpr{token, nullptr, nullptr};
        if (esOperador(token)) {
            nodo->der = pila.top(); pila.pop();   // el segundo operando salio primero
            nodo->izq = pila.top(); pila.pop();
        }
        pila.push(nodo);
    }
    return pila.top();
}

int evaluar(NodoExpr* raiz) {   // recorrido postorder: izquierda, derecha, nodo
    if (!esOperador(raiz->valor)) return std::stoi(raiz->valor);
    int a = evaluar(raiz->izq), b = evaluar(raiz->der);
    if (raiz->valor == "+") return a + b;
    // ... mismo patron para -, *, /
    return a / b;
}
Salida real (compilado y corrido)
postfija: "5 1 2 + 4 * + 3 -"
infija reconstruida desde el arbol: ((5 + ((1 + 2) * 4)) - 3)
evaluada recorriendo el arbol (postorder): 14

Ojo con el orden al sacar los dos operandos de la pila: el que salió primero (el tope) es el operando DERECHO, no el izquierdo — porque entró último. Si los invertís, operaciones conmutativas como + dan el mismo resultado por casualidad, pero - y / dan la respuesta al revés sin ningún error del compilador que te avise.

2.9 Orden topológico y detección de ciclos

Un orden topológico de un grafo DIRIGIDO responde: "¿en qué orden puedo procesar estos nodos de forma que nunca procese uno antes que todo lo que depende de él?" — el ejemplo de todos los días: prerrequisitos de materias. El algoritmo de Kahn (BFS con grado de entrada) es directo: empezar por los nodos sin prerrequisitos (grado de entrada 0), "consumirlos" quitando sus aristas salientes, y repetir con los que quedaron en grado 0. Si al final quedan nodos sin procesar, es porque hay un ciclo — y un orden topológico simplemente no existe si hay un ciclo (sería pedirle a A que vaya antes que B, que vaya antes que A).

topologico.cppc++
std::vector<int> ordenTopologico(int n, std::vector<std::vector<int> >& adj, bool& hayCiclo) {
    std::vector<int> gradoEntrada(n, 0);
    for (int u = 0; u < n; u++) for (int v : adj[u]) gradoEntrada[v]++;

    std::queue<int> cola;
    for (int i = 0; i < n; i++) if (gradoEntrada[i] == 0) cola.push(i);

    std::vector<int> orden;
    while (!cola.empty()) {
        int u = cola.front(); cola.pop();
        orden.push_back(u);
        for (int v : adj[u]) if (--gradoEntrada[v] == 0) cola.push(v);
    }
    hayCiclo = (int)orden.size() != n;   // si quedo alguno sin grado 0, hay ciclo
    return orden;
}

Nota de obraEsto es la versión general de delos_renumber.f90 (ya visto en el tema 2.3, BFS puro): acá el BFS no solo visita, sino que respeta una DEPENDENCIA entre nodos. En un proyecto de software real, exactamente este algoritmo es el que resuelve "en qué orden compilo estos módulos" cuando uno depende de otro — y el "hay ciclo" es, literalmente, el error de "dependencia circular" que da un compilador o un gestor de paquetes.

2.10 Árbol de expansión mínima: Kruskal

Dado un grafo con pesos, un árbol de expansión mínima (MST) conecta TODOS los nodos con el MENOR peso total posible, sin ciclos. Kruskal es greedy (tema 2.4 de ruta-fem) aplicado a esto: ordenar todas las aristas por peso ascendente, y tomar cada una SALVO que conecte dos nodos que ya están en el mismo grupo (eso formaría un ciclo, y un árbol no tiene ciclos). "¿Ya están en el mismo grupo?" es EXACTAMENTE la pregunta que resuelve Union-Find (tema 2.7) — por eso este tema va después, reusa esa estructura entera sin cambiar una línea.

kruskal.cppc++
struct Arista { int u, v, peso; };

std::sort(aristas.begin(), aristas.end(), [](const Arista& a, const Arista& b) {
    return a.peso < b.peso;
});

int pesoTotal = 0;
for (auto& a : aristas) {
    if (encontrar(a.u) != encontrar(a.v)) {   // Union-Find del tema 2.7, sin cambios
        unir(a.u, a.v);
        pesoTotal += a.peso;
    }
    // si encontrar(a.u) == encontrar(a.v): formaria un ciclo, se descarta
}
Salida real (compilado y corrido) — 5 nodos, 6 aristas con peso
(0,2) peso=1 -> ACEPTADA
(1,2) peso=2 -> ACEPTADA
(3,4) peso=3 -> ACEPTADA
(0,1) peso=4 -> descartada (forma ciclo)
(1,3) peso=5 -> ACEPTADA
(2,3) peso=8 -> descartada (forma ciclo)
arbol de expansion minima: 4 aristas, peso total=11

Con n nodos, un árbol de expansión siempre tiene exactamente n-1 aristas (4 en el ejemplo, con 5 nodos) — ni una menos (no conectaría todo) ni una más (formaría un ciclo). La alternativa es Prim: en vez de ordenar TODAS las aristas de una, crece el árbol desde un nodo inicial usando una cola de prioridad (tema 2.3) para elegir siempre la arista más barata que toque el árbol actual — mejor cuando el grafo es muy denso, Kruskal suele ser más simple de razonar cuando es disperso (el caso típico de una malla).

Nota de obraSi alguna vez el proyecto de tu papá necesitara minimizar el costo TOTAL de conectar una red (cableado, tuberías, una malla con costo de arista real en vez de solo adyacencia), esto es la pieza exacta — mismo patrón greedy + Union-Find que el emparejado de triángulos de DELOS-3D (tema 2.4 de ruta-fem), aplicado a un problema distinto.
