3.1 Vectores y matrices en código

Sin librerías todavía: una matriz es vector<vector<double>>, y multiplicar es, literalmente, el producto punto del tema 1.1.1 de matemáticas repetido fila por fila.

matrices.cppc++
using Matriz = std::vector<std::vector<double>>;
using Vector = std::vector<double>;

Vector multiplicar(const Matriz& A, const Vector& x) {
    int n = A.size(), m = A[0].size();
    Vector resultado(n, 0.0);
    for (int i = 0; i < n; i++)
        for (int j = 0; j < m; j++)
            resultado[i] += A[i][j] * x[j];
    return resultado;
}
Salida real — mismo ejemplo del tema 1.1.2 de matemáticas
A*x = [11, 3]  (esperado: [11, 3])

Para proyectos reales, esto se reemplaza por una librería como Eigen (solo headers, gratis, #include <Eigen/Dense>) que hace lo mismo pero optimizado y con sintaxis matemática (A*x literalmente funciona). Vale la pena escribirlo a mano primero — así entendés qué hace Eigen por debajo en vez de tratarlo como caja negra.

3.2 Eliminación gaussiana

El algoritmo exacto del tema 1.1.3/1.4.1 de matemáticas, en código: eliminar hacia abajo, después sustitución hacia atrás.

gauss.cppc++
Vector eliminacionGaussiana(Matriz A, Vector b) {
    int n = A.size();
    for (int col = 0; col < n; col++)
        for (int fila = col+1; fila < n; fila++) {
            double factor = A[fila][col] / A[col][col];
            for (int k = col; k < n; k++) A[fila][k] -= factor * A[col][k];
            b[fila] -= factor * b[col];
        }
    Vector x(n);
    for (int i = n-1; i >= 0; i--) {           // sustitucion hacia atras
        double suma = b[i];
        for (int j = i+1; j < n; j++) suma -= A[i][j]*x[j];
        x[i] = suma / A[i][i];
    }
    return x;
}
Salida real — el mismo sistema 3×3 del tema 1.1.3
solucion: x=1 y=2 z=3 (esperado: 1,2,3)

Nota: A[col][col] es el "pivote" — si es 0 (o muy chico), el algoritmo se rompe (división por cero o error numérico grande). Una implementación robusta de verdad hace pivoteo parcial: antes de eliminar, intercambia filas para poner el valor más grande posible en la posición del pivote. No lo incluí acá para no oscurecer el algoritmo base, pero es lo primero que le faltaría a este código para ser production-ready.

3.3 Métodos iterativos: Gauss-Seidel

El mismo sistema y el mismo procedimiento del tema 1.4.2 de matemáticas, en código — despejar cada variable de su ecuación, iterar usando siempre el valor más reciente.

gauss_seidel.cppc++
double x = 0, y = 0;
for (int i = 1; i <= 4; i++) {
    x = (7 + y) / 4.0;
    y = (5 + x) / 3.0;
}
Salida real
iter 1: x=1.7500 y=2.2500
iter 2: x=2.3125 y=2.4375
iter 3: x=2.3594 y=2.4531
iter 4: x=2.3633 y=2.4544
exacto: x=2.3636 y=2.4545

Coincide, cifra por cifra, con la tabla del tema 1.4.2. La condición real para que Gauss-Seidel converja (no siempre lo hace) es que la matriz sea diagonalmente dominante — en cada fila, el elemento de la diagonal es mayor en valor absoluto que la suma de los demás de esa fila. Vale la pena verificar esto ANTES de confiar en la convergencia, no asumirlo.

3.4 Eigenvalores: método de la potencia

Misma matriz, mismo procedimiento del tema 1.4.3 — multiplicar repetidamente, normalizar por el componente más grande.

potencia.cppc++
double A[2][2] = {{4,1},{2,3}};
double x[2] = {1,0};
for (int it = 1; it <= 4; it++) {
    double nuevo[2] = {A[0][0]*x[0]+A[0][1]*x[1], A[1][0]*x[0]+A[1][1]*x[1]};
    double escala = std::fabs(nuevo[0]) > std::fabs(nuevo[1]) ? nuevo[0] : nuevo[1];
    x[0] = nuevo[0]/escala; x[1] = nuevo[1]/escala;
}
Salida real
iter 1: vector=(1.0000, 0.5000), escala=4.0000
iter 2: vector=(1.0000, 0.7778), escala=4.5000
iter 3: vector=(1.0000, 0.9070), escala=4.7778
iter 4: vector=(1.0000, 0.9621), escala=4.9070
esperado: converge a vector (1,1), eigenvalor 5

Idéntico, número por número, a la tabla del tema 1.4.3. Este es el método que un programa de dinámica estructural usaría para encontrar la frecuencia natural dominante sin resolver el polinomio característico completo — inviable para una matriz de miles de filas.

3.5 Interpolación de Lagrange

La fórmula general del tema 1.4.6, para cualquier cantidad de puntos — la misma fórmula que, restringida a 2 o 3 puntos, son las funciones de forma de un elemento finito.

lagrange.cppc++
double interpolarLagrange(const Vector& xs, const Vector& ys, double xEval) {
    double resultado = 0.0;
    int n = xs.size();
    for (int i = 0; i < n; i++) {
        double Li = 1.0;
        for (int j = 0; j < n; j++) {
            if (j == i) continue;
            Li *= (xEval - xs[j]) / (xs[i] - xs[j]);
        }
        resultado += ys[i] * Li;
    }
    return resultado;
}
Salida real — 3 puntos de \(y=x^2\) en \(x=0,1,2\), evaluado en puntos nuevos
P(0.5) = 0.25  (x^2 real = 0.25)
P(1.5) = 2.25  (x^2 real = 2.25)
P(3) = 9       (x^2 real = 9)

Con solo 3 puntos, el polinomio reconstruye \(x^2\) EXACTO en cualquier punto — incluso fuera del rango original (\(x=3\)). Esto no es casualidad: como \(x^2\) es, de por sí, un polinomio de grado 2, y Lagrange con 3 puntos construye exactamente ESE grado, no hay error de aproximación posible. Con una función que NO sea polinomial (como \(\sin x\)), sí habría error, más grande cuanto más lejos del rango de los puntos originales.

3.6 Integración numérica

Trapecio y Simpson (tema 1.4.4), probados contra una integral que se puede calcular a mano para verificar el error de cada uno.

integracion.cppc++
double f(double x) { return x*x; }  // integral de 0 a 1 = 1/3

double trapecio(double a, double b, int n) {
    double h = (b-a)/n, suma = (f(a)+f(b))/2.0;
    for (int i = 1; i < n; i++) suma += f(a+i*h);
    return suma*h;
}

double simpson(double a, double b, int n) {  // n debe ser par
    double h = (b-a)/n, suma = f(a)+f(b);
    for (int i = 1; i < n; i++) suma += f(a+i*h) * (i%2==0 ? 2 : 4);
    return suma*h/3.0;
}
Salida real — \(\int_0^1 x^2\,dx\), 10 subdivisiones
trapecio (n=10): 0.335000
simpson  (n=10): 0.333333
exacto (1/3):    0.333333

Simpson da el valor EXACTO con solo 10 subdivisiones; trapecio se queda con un error de ~0.5%. La razón: Simpson usa una parábola en cada tramo, y \(x^2\) ES una parábola — error cero por construcción. Con una curva más complicada que una parábola, Simpson seguiría siendo más preciso que trapecio para el mismo \(n\), pero no exacto.

3.7 Búsqueda de raíces: Newton-Raphson

El mismo ejemplo exacto del tema 1.4.5 de matemáticas — calcular \(\sqrt2\) sin usar la función de raíz del lenguaje.

newton.cppc++
double f(double x)  { return x*x - 2; }
double fp(double x) { return 2*x; }

double x = 1.0;
for (int i = 1; i <= 4; i++)
    x = x - f(x)/fp(x);
Salida real
iter 1: x=1.50000000
iter 2: x=1.41666667
iter 3: x=1.41421569
iter 4: x=1.41421356
sqrt(2) real: 1.41421356

Idéntico al ejemplo a mano del tema 1.4.5, hasta la 8ª cifra decimal.

3.8 Matrices dispersas (CSR)

Una matriz de rigidez real (de miles o millones de nodos) es dispersa: cada nodo se conecta solo con un puñado de vecinos, así que casi todos sus valores son cero. Guardarla como vector<vector<double>> (llena) desperdicia memoria de forma brutal. El formato CSR (Compressed Sparse Row) guarda solo los valores no-cero, más dos arrays de índices para saber a qué fila/columna pertenece cada uno.

csr.cppc++
struct MatrizCSR {
    std::vector<double> valores;      // valores no-cero, en orden por fila
    std::vector<int> columnas;        // a que columna pertenece cada valor
    std::vector<int> inicioFila;      // donde empieza cada fila en "valores"

    Vector multiplicar(const Vector& x) const {
        int n = inicioFila.size() - 1;
        Vector resultado(n, 0.0);
        for (int fila = 0; fila < n; fila++)
            for (int idx = inicioFila[fila]; idx < inicioFila[fila+1]; idx++)
                resultado[fila] += valores[idx] * x[columnas[idx]];   // nunca toca los ceros
        return resultado;
    }
};
Salida real — matriz tridiagonal 5×5 (como una cadena de resortes), \(x=(1,1,1,1,1)\)
K*x = 1 0 0 0 1
memoria llena (5x5): 25 numeros
memoria CSR: 32 numeros (13 no-cero + indices)

Con n=5, CSR pierde — 32 números contra 25. Esto es real, no un error: para una matriz TAN chica, el costo de los índices supera el ahorro de no guardar ceros. La ganancia de CSR es asintótica, no inmediata — recién se nota en escala real:

n (nodos)Llena (n²)CSR (≈7n, misma dispersión)
52532
1010067
10010.000697
1.0001.000.0006.997
10.000100.000.00069.997

El cruce pasa entre n=5 y n=10; a partir de ahí, la ventaja de CSR crece sin límite. Con 10.000 nodos, CSR usa 1400 veces menos memoria que una matriz llena — la diferencia entre un modelo real que corre y uno que no entra en la RAM de la máquina.
