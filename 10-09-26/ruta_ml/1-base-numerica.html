1.1 Álgebra lineal aplicada: la matriz como herramienta de ML

En ML casi todo es multiplicar matrices. Los datos son una matriz \(X\) de \(n\) filas (ejemplos) por \(d\) columnas (características); los pesos de un modelo lineal son un vector \(w\) de largo \(d\); y predecir es calcular \(Xw\). Una capa de una red neuronal es lo mismo con \(W\) en vez de \(w\). Por eso la primera pieza de esta ruta no es "un algoritmo": es tener una Matriz y un Vector cómodos y rápidos.

No la reescribas de cero. Ya tenés Matriz<T> y Vector2D/3D en codigo/PROYECTO/, y el tema 3.1 de la Ruta de Código hace el producto matriz-vector. Lo que ML necesita además es: transpuesta, producto matriz-matriz, producto elemento a elemento (Hadamard), suma por filas/columnas y un dot entre vectores.

  • Layout: guardar los \(n \times d\) valores en una sola tira de memoria, fila a fila (row-major). Es lo que usa NumPy, Eigen por defecto no (usa column-major), y es lo que hace que el tema 1.7 funcione.
  • Dimensiones: \((n \times d)(d \times k) \to (n \times k)\). El 80% de los bugs de ML en código son dimensiones que no cierran; hacé que tu clase lo verifique y lance una excepción con un mensaje claro.
  • Costo: multiplicar \((n \times d)\) por \((d \times k)\) cuesta \(n \cdot d \cdot k\) multiplicaciones.

1.2 Sistemas de ecuaciones y mínimos cuadrados

La regresión lineal es un problema de mínimos cuadrados: encontrar \(w\) que haga mínimo \(\|Xw - y\|^2\). Derivando e igualando a cero sale un sistema de ecuaciones, las ecuaciones normales: \(X^T X\, w = X^T y\). Y ese sistema ya lo sabés resolver: es el Gauss de Chapra (con pivoteo parcial). Es decir, tu primer modelo de ML es la eliminación gaussiana aplicada a una matriz que armaste con tus datos.

minimos_cuadrados.cppc++
#include <iostream>
#include <vector>
#include <random>
#include <cmath>
#include <utility>

using Matriz = std::vector<std::vector<double>>;
using Vector = std::vector<double>;

// Gauss con pivoteo parcial (el de Chapra, ahora con el intercambio de filas)
Vector resolver(Matriz A, Vector b) {
    int n = A.size();
    for (int c = 0; c < n; ++c) {
        int p = c;
        for (int f = c + 1; f < n; ++f) if (std::fabs(A[f][c]) > std::fabs(A[p][c])) p = f;
        std::swap(A[c], A[p]); std::swap(b[c], b[p]);
        for (int f = c + 1; f < n; ++f) {
            double m = A[f][c] / A[c][c];
            for (int k = c; k < n; ++k) A[f][k] -= m * A[c][k];
            b[f] -= m * b[c];
        }
    }
    Vector x(n);
    for (int i = n - 1; i >= 0; --i) {
        double s = b[i];
        for (int j = i + 1; j < n; ++j) s -= A[i][j] * x[j];
        x[i] = s / A[i][i];
    }
    return x;
}

int main() {
    std::mt19937 gen(42);
    std::uniform_real_distribution<double> ux(0, 10);
    std::normal_distribution<double> ruido(0, 0.5);

    int n = 200;
    Matriz X(n, Vector(2));                                 // matriz de diseno: columna de 1 y columna de x
    Vector y(n);
    for (int i = 0; i < n; ++i) { double x = ux(gen); X[i] = {1.0, x}; y[i] = 3.0 * x + 2.0 + ruido(gen); }

    // ecuaciones normales:  (X^T X) w = X^T y
    Matriz XtX(2, Vector(2, 0.0));
    Vector Xty(2, 0.0);
    for (int i = 0; i < n; ++i)
        for (int a = 0; a < 2; ++a) {
            Xty[a] += X[i][a] * y[i];
            for (int b = 0; b < 2; ++b) XtX[a][b] += X[i][a] * X[i][b];
        }
    Vector w = resolver(XtX, Xty);
    std::cout << "ordenada = " << w[0] << "  (real 2)    pendiente = " << w[1] << "  (real 3)\n";
}
Salida real
ordenada = 2.05733  (real 2)    pendiente = 2.99335  (real 3)

Los datos eran \(y = 3x + 2\) más ruido; el modelo recuperó ordenada ≈ 2.06 y pendiente ≈ 2.99. Que no dé exactamente 2 y 3 no es un error: el ruido hace que el mínimo de esta muestra sea ligeramente distinto del real.

OjoNo inviertas la matriz. Se resuelve el sistema (Gauss/LU), no se calcula \((X^TX)^{-1}\): es más lento y menos preciso. Además, formar \(X^TX\) eleva al cuadrado el número de condición; por eso las librerías serias usan QR o SVD en vez de las ecuaciones normales. Para este curso las normales alcanzan, pero guardá la idea (la retomamos en 2.3 con regularización).

1.3 Probabilidad y estadística en código

Tu repaso de probabilidad y estadística va por tu cuenta; acá va la parte de código: generar datos aleatorios reproducibles, y calcular lo que el resto de la ruta usa todo el tiempo (media, varianza, covarianza, desvío).

En C++ se usa <random>: un motor (std::mt19937, con semilla fija para que el experimento sea repetible) y una distribución (std::normal_distribution, std::uniform_real_distribution). La semilla fija es oro: cuando un modelo falla, necesitás poder reproducir exactamente los mismos datos.

estadistica.cppc++
#include <iostream>
#include <vector>
#include <random>
#include <cmath>

int main() {
    std::mt19937 gen(42);                                   // semilla fija: reproducible
    std::normal_distribution<double> normal(10.0, 2.0);     // media 10, desvío 2
    const int n = 100000;
    std::vector<double> v(n);
    for (double& x : v) x = normal(gen);

    double suma = 0;
    for (double x : v) suma += x;
    double media = suma / n;

    double ss = 0;
    for (double x : v) ss += (x - media) * (x - media);
    double varianza = ss / (n - 1);                         // muestral: n-1

    int dentro = 0;
    for (double x : v) if (std::fabs(x - media) < std::sqrt(varianza)) ++dentro;

    std::cout << "media     = " << media << "   (teorica 10)\n";
    std::cout << "varianza  = " << varianza << "   (teorica 4)\n";
    std::cout << "dentro de 1 desvio = " << double(dentro) / n << "   (teorico 0.6827)\n";
}
Salida real
media     = 10.0027   (teorica 10)
varianza  = 4.00287   (teorica 4)
dentro de 1 desvio = 0.68209   (teorico 0.6827)
  • La varianza muestral divide por \(n-1\), no por \(n\) (corrección de Bessel). Con \(n=100000\) no se nota; con \(n=5\) sí.
  • La proporción dentro de un desvío da 0.6821 y la teórica es 0.6827: más muestras acercan los dos números (ley de los grandes números).

1.4 Datos: cargar, normalizar y separar en entrenamiento y prueba

Los modelos no ven "la realidad": ven una tabla. El 80% del trabajo práctico es preparar esa tabla. Tres reglas que aparecen en todos lados:

  • Estandarizar cada característica (restar la media, dividir por el desvío) para que ninguna domine por tener unidades más grandes (la altura en cm contra el peso en kg). Sin esto, el descenso por gradiente (1.6) se vuelve lentísimo.
  • Separar antes de calcular nada: el conjunto de prueba representa datos que el modelo nunca vio. Si calculás la media usando también esos datos, el modelo "espió" el examen. Esto se llama fuga de datos (data leakage) y es el error más común y más caro.
  • Reproducibilidad: mezclar los índices con una semilla fija.
zscore_split.cppc++
#include <iostream>
#include <vector>
#include <random>
#include <algorithm>
#include <numeric>
#include <cmath>

int main() {
    std::mt19937 gen(7);
    std::normal_distribution<double> alturas(170, 10), pesos(70, 15);
    const int n = 1000;
    std::vector<std::vector<double>> X(n, std::vector<double>(2));
    for (auto& fila : X) { fila[0] = alturas(gen); fila[1] = pesos(gen); }

    // 1) mezclar los indices y separar 80% / 20%  (ANTES de calcular estadisticas)
    std::vector<int> idx(n);
    std::iota(idx.begin(), idx.end(), 0);
    std::shuffle(idx.begin(), idx.end(), gen);
    int nTrain = n * 8 / 10;

    // 2) media y desvio SOLO con el train
    double media[2] = {0, 0}, desvio[2] = {0, 0};
    for (int k = 0; k < nTrain; ++k) for (int j = 0; j < 2; ++j) media[j] += X[idx[k]][j] / nTrain;
    for (int k = 0; k < nTrain; ++k) for (int j = 0; j < 2; ++j) desvio[j] += std::pow(X[idx[k]][j] - media[j], 2) / nTrain;
    for (int j = 0; j < 2; ++j) desvio[j] = std::sqrt(desvio[j]);

    // 3) estandarizar todo con ESAS estadisticas
    for (auto& fila : X) for (int j = 0; j < 2; ++j) fila[j] = (fila[j] - media[j]) / desvio[j];

    double mTrain = 0, mTest = 0;
    for (int k = 0; k < nTrain; ++k) mTrain += X[idx[k]][0] / nTrain;
    for (int k = nTrain; k < n; ++k) mTest += X[idx[k]][0] / (n - nTrain);
    std::cout << "train = " << nTrain << "  test = " << n - nTrain << "\n";
    std::cout << "media de la altura estandarizada: train = " << mTrain << "  test = " << mTest << "\n";
}
Salida real
train = 800  test = 200
media de la altura estandarizada: train = 4.19283e-15  test = -0.219416

Mirá la última línea: la media de la altura estandarizada en train es 0 (4e-15, ruido de coma flotante) por construcción, pero en test da −0.22. No es un bug: el test usó las estadísticas del train, y su media real es distinta. Si la forzaras a 0 usando datos del test, estarías filtrando información.

1.5 Derivadas y gradiente en código (y cómo comprobarlos)

Entrenar un modelo es bajar una "montaña" de error. La dirección de máxima subida es el gradiente: el vector de derivadas parciales. Para cualquier función \(f(x,y)\), el gradiente es \((\partial f/\partial x,\ \partial f/\partial y)\). En redes neuronales, la regla de la cadena aplicada capa por capa (backpropagation, 3.3) calcula ese gradiente para millones de parámetros.

Tenés una forma de calcular derivadas sin cálculo: la diferencia central, \(f'(x) \approx (f(x+h) - f(x-h)) / 2h\) (la misma que usaste en derivada(f, x) con lambdas). Sirve para algo más importante que calcular: verificar el gradiente que derivaste a mano. Esa técnica se llama gradient check y es la herramienta de depuración más valiosa del bloque de redes neuronales.

gradcheck.cppc++
#include <iostream>
#include <cmath>
#include <functional>
#include <vector>

// f(x, y) = x^2 * y + sin(y)
double f(double x, double y) { return x * x * y + std::sin(y); }

int main() {
    double x = 1.5, y = 0.8;
    // gradiente analitico (a mano): df/dx = 2xy ; df/dy = x^2 + cos(y)
    double gx = 2 * x * y, gy = x * x + std::cos(y);

    // gradiente numerico: diferencia central
    for (double h : {1e-1, 1e-3, 1e-5, 1e-8}) {
        double nx = (f(x + h, y) - f(x - h, y)) / (2 * h);
        double ny = (f(x, y + h) - f(x, y - h)) / (2 * h);
        double err = std::sqrt((nx - gx) * (nx - gx) + (ny - gy) * (ny - gy)) /
                     std::sqrt(gx * gx + gy * gy);
        std::cout << "h = " << h << "   error relativo = " << err << "\n";
    }
    std::cout << "analitico: (" << gx << ", " << gy << ")\n";
}
Salida real
h = 0.1   error relativo = 0.000305388
h = 0.001   error relativo = 3.05541e-08
h = 1e-05   error relativo = 8.19652e-12
h = 1e-08   error relativo = 7.15366e-09
analitico: (2.4, 2.94671)

Fijate en la columna del error: baja con \(h\) hasta \(10^{-5}\) (8e-12) y vuelve a subir con \(10^{-8}\) (7e-9). Dos errores compiten: el de aproximación (baja con \(h\)) y el de redondeo (sube cuando restás dos números casi iguales). El mejor \(h\) está en el medio.

1.6 Optimización: el descenso por gradiente

Casi todo el ML moderno es: definir una función de pérdida \(L(\theta)\) y buscar los parámetros \(\theta\) que la minimicen, dando pasos en dirección contraria al gradiente: \(\theta \leftarrow \theta - \eta\, \nabla L(\theta)\). El número \(\eta\) es la tasa de aprendizaje (learning rate), y es el hiperparámetro más importante que vas a tocar.

Con \(f(x) = (x-3)^2\) el paso es \(x \leftarrow x - \eta \cdot 2(x-3)\). Cada paso multiplica la distancia al mínimo por \((1 - 2\eta)\). Si \(|1-2\eta| < 1\) converge; si no, no. Con la cuenta a la vista, el resultado se puede predecir antes de ejecutar:

gd_lr.cppc++
#include <iostream>

// f(x) = (x - 3)^2   ->   f'(x) = 2(x - 3)   ->   minimo en x = 3
int main() {
    for (double lr : {0.1, 0.9, 1.0, 1.1}) {
        double x = 0.0;
        for (int it = 0; it < 20; ++it) x -= lr * 2 * (x - 3);
        std::cout << "lr = " << lr << "   x tras 20 pasos = " << x << "\n";
    }
}
Salida real
lr = 0.1   x tras 20 pasos = 2.96541
lr = 0.9   x tras 20 pasos = 2.96541
lr = 1   x tras 20 pasos = 0
lr = 1.1   x tras 20 pasos = -112.013
  • lr = 0.1: factor 0.8, converge suave. lr = 0.9: factor −0.8, oscila de un lado a otro pero converge, igual de lento (el mismo 2.96541).
  • lr = 1.0: factor −1, queda atrapado saltando entre dos puntos para siempre (x=0 y x=6). lr = 1.1: factor −1.2, diverge (x = −112 y creciendo).

Esto conecta con Chapra: el método de Newton elige el paso usando la segunda derivada y por eso en una parábola llega en un solo paso; el descenso por gradiente simple necesita ajustar \(\eta\) a mano. Los optimizadores del tema 3.6 (momentum, Adam) son maneras de automatizar esa elección.

1.7 Eficiencia: por qué el orden de los bucles importa

Entrenar modelos significa multiplicar matrices millones de veces, así que el costo constante importa tanto como el Big-O. La memoria funciona por líneas de caché: cuando leés un double, el procesador trae también los vecinos. Si tu bucle recorre la memoria en el orden en que está guardada, usás todo lo que trajo; si "salta" entre filas, tiras la mayor parte.

Probalo con la misma multiplicación \(C = AB\) de 400×400, escrita con dos órdenes de bucles. Ambos hacen exactamente \(400^3\) multiplicaciones y dan el mismo resultado:

matmul_orden.cppc++
#include <iostream>
#include <vector>
#include <chrono>

using Mat = std::vector<double>;                            // n*n en una sola tira (fila a fila)

template <class F> double ms(F f) {
    auto t = std::chrono::steady_clock::now();
    f();
    return std::chrono::duration<double, std::milli>(std::chrono::steady_clock::now() - t).count();
}

int main() {
    const int n = 400;
    Mat A(n * n, 1.0), B(n * n, 2.0), C1(n * n, 0.0), C2(n * n, 0.0);

    double t1 = ms([&] {                                    // orden i-j-k: B se recorre "saltando" filas
        for (int i = 0; i < n; ++i) for (int j = 0; j < n; ++j) {
            double s = 0;
            for (int k = 0; k < n; ++k) s += A[i * n + k] * B[k * n + j];
            C1[i * n + j] = s;
        }
    });
    double t2 = ms([&] {                                    // orden i-k-j: todo se recorre seguido
        for (int i = 0; i < n; ++i) for (int k = 0; k < n; ++k) {
            double a = A[i * n + k];
            for (int j = 0; j < n; ++j) C2[i * n + j] += a * B[k * n + j];
        }
    });
    std::cout << "i-j-k: " << t1 << " ms   i-k-j: " << t2 << " ms   mismo resultado: " << (C1 == C2) << "\n";
}
Salida real
i-j-k: 108.634 ms   i-k-j: 15.9686 ms   mismo resultado: 1

El orden i-k-j es unas 6.8 veces más rápido en esta Mac (-O2; el número exacto depende de tu máquina, así que corrélo en tu PC con Windows para comparar). La razón: en i-j-k, el bucle interior recorre B[k*n+j] saltando n posiciones por vez (una columna); en i-k-j recorre B[k*n+j] con j creciendo (una fila, seguida en memoria).

MediciónLos tiempos de este tema son de mi Mac, medidos una vez. No los cites como universales: lo que se mantiene es la relación (acceso seguido gana a acceso con saltos), no el valor absoluto.

1.8 Ver los resultados: escribir un SVG desde C++

Un modelo que no podés mirar es un modelo que no entendés. Antes de aprender matplotlib (4.3), podés dibujar con lo que ya tenés: un archivo SVG es texto con etiquetas (<circle>, <line>) que el navegador abre sin instalar nada. Es la misma técnica que vas a usar para dibujar la malla del Integrador 2.

El truco es una pequeña función que convierte coordenadas del problema a coordenadas de pantalla, teniendo en cuenta que en SVG el eje \(y\) crece hacia abajo:

svg_scatter.cppc++
#include <fstream>
#include <vector>
#include <random>
#include <string>

struct P { double x, y; int clase; };

// Escribe un SVG: puntos coloreados por clase + una recta (y = m x + c).  Se abre en el navegador.
void escribirSVG(const std::string& ruta, const std::vector<P>& pts, double m, double c,
                 double xmin, double xmax, double ymin, double ymax) {
    const int W = 480, H = 360;
    auto X = [&](double x) { return (x - xmin) / (xmax - xmin) * W; };
    auto Y = [&](double y) { return H - (y - ymin) / (ymax - ymin) * H; };    // el eje y de SVG crece hacia abajo
    std::ofstream f(ruta);
    f << "<svg xmlns='http://www.w3.org/2000/svg' width='" << W << "' height='" << H << "' style='background:#fff'>\n";
    for (const P& p : pts)
        f << "<circle cx='" << X(p.x) << "' cy='" << Y(p.y) << "' r='3' fill='" << (p.clase ? "#d95f02" : "#1b9e77") << "'/>\n";
    f << "<line x1='" << X(xmin) << "' y1='" << Y(m * xmin + c) << "' x2='" << X(xmax) << "' y2='" << Y(m * xmax + c)
      << "' stroke='black' stroke-width='2'/>\n</svg>\n";
}

int main() {
    std::mt19937 g(1);
    std::normal_distribution<double> r(0, 1);
    std::vector<P> pts;
    for (int i = 0; i < 150; ++i) { int c = i % 2; double mu = c ? 1.5 : -1.5; pts.push_back({mu + r(g), mu + r(g), c}); }
    escribirSVG("puntos.svg", pts, -1.0, 0.0, -5, 5, -5, 5);     // la frontera ideal: x + y = 0
}
