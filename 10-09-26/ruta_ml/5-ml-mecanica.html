5.2 Descubrir una ley física con datos: la viga en voladizo

El primer ejemplo conecta lo que estudiás en mecánica con lo que programás en ML. La flecha en el extremo de una viga en voladizo con carga puntual \(P\) es \(\delta = PL^3/(3EI)\). Imaginá que no conocés esa fórmula y tenés 300 mediciones de \(\delta\) para distintos \(L\) y \(P\), cada una con 2% de error de medición. Una ley de potencias se vuelve lineal con logaritmos: \(\ln\delta = a + b\ln L + c\ln P\). Eso es una regresión lineal (1.2) y recupera los exponentes:

surrogate_viga.cppc++
#include <iostream>
#include <vector>
#include <random>
#include <cmath>
#include <utility>

using Matriz = std::vector<std::vector<double>>;
using Vector = std::vector<double>;

Vector resolver(Matriz A, Vector b) {
    int n = A.size();
    for (int c = 0; c < n; ++c) {
        int p = c;
        for (int f = c + 1; f < n; ++f) if (std::fabs(A[f][c]) > std::fabs(A[p][c])) p = f;
        std::swap(A[c], A[p]); std::swap(b[c], b[p]);
        for (int f = c + 1; f < n; ++f) { double m = A[f][c] / A[c][c]; for (int k = c; k < n; ++k) A[f][k] -= m * A[c][k]; b[f] -= m * b[c]; }
    }
    Vector x(n);
    for (int i = n - 1; i >= 0; --i) { double s = b[i]; for (int j = i + 1; j < n; ++j) s -= A[i][j] * x[j]; x[i] = s / A[i][i]; }
    return x;
}

int main() {
    // viga en voladizo: flecha en el extremo  delta = P L^3 / (3 E I)
    const double E = 210e9, base = 0.05, alto = 0.10, I = base * alto * alto * alto / 12;
    auto flecha = [&](double L, double P) { return P * L * L * L / (3 * E * I); };

    std::mt19937 gen(21);
    std::uniform_real_distribution<double> uL(0.5, 3.0), uP(100, 2000);
    std::normal_distribution<double> ruido(0, 0.02);        // 2% de error de medicion
    const int n = 300;
    Matriz X(n, Vector(3));
    Vector y(n);
    for (int i = 0; i < n; ++i) {
        double L = uL(gen), P = uP(gen);
        double medida = flecha(L, P) * (1 + ruido(gen));
        X[i] = {1.0, std::log(L), std::log(P)};             // modelo lineal en LOGARITMOS
        y[i] = std::log(medida);
    }
    Matriz A(3, Vector(3, 0.0));                            // ecuaciones normales
    Vector r(3, 0.0);
    for (int i = 0; i < n; ++i) for (int a = 0; a < 3; ++a) { r[a] += X[i][a] * y[i]; for (int b = 0; b < 3; ++b) A[a][b] += X[i][a] * X[i][b]; }
    Vector w = resolver(A, r);

    std::cout << "exponente de L  : " << w[1] << "   (teoria: 3)\n";
    std::cout << "exponente de P  : " << w[2] << "   (teoria: 1)\n";
    std::cout << "ordenada        : " << w[0] << "   (teoria: " << -std::log(3 * E * I) << ")\n";
    double L = 2.0, P = 1000.0;
    double pred = std::exp(w[0] + w[1] * std::log(L) + w[2] * std::log(P));
    std::cout << "flecha para L = 2 m, P = 1000 N:  modelo = " << pred * 1000 << " mm   exacta = " << flecha(L, P) * 1000 << " mm\n";
}
Salida real
exponente de L  : 2.99915   (teoria: 3)
exponente de P  : 0.999811   (teoria: 1)
ordenada        : -14.7785   (teoria: -14.7806)
flecha para L = 2 m, P = 1000 N:  modelo = 3.04813 mm   exacta = 3.04762 mm
  • Los exponentes recuperados son 2.99915 (teoría: 3) y 0.99981 (teoría: 1): la regresión redescubrió que la flecha crece con \(L^3\) y con \(P\) a partir de datos con ruido.
  • La ordenada \(-14.7785\) corresponde a \(-\ln(3EI)\) (teoría: −14.7806). De ahí se podría despejar \(EI\), o sea, identificar la rigidez de la viga midiendo.
  • Predicción para \(L=2\) m, \(P=1000\) N: modelo 3.0481 mm contra exacta 3.0476 mm (error de 0.02%).

Por qué esto importa: el truco del logaritmo (transformar para volver lineal) y el uso de la regresión como herramienta de identificación de parámetros físicos son la base de gran parte del ajuste experimental en ingeniería: ensayos de tracción, fatiga, curvas de desgaste.

SintéticoLos datos de este ejemplo son sintéticos: los generé yo con la fórmula exacta más 2% de ruido. En un ensayo real el modelo puede no ser de potencia, el ruido no ser multiplicativo, y las variables estar correlacionadas. El código es el mismo; lo difícil es el análisis de lo que sale.

5.3 Modelos sustitutos (surrogates) de simulaciones FEM

Una simulación FEM puede tardar minutos u horas. Si querés explorar miles de diseños (variar espesores, cargas, materiales), no alcanza el tiempo. La idea del modelo sustituto: correr la simulación unas decenas o cientos de veces, entrenar un modelo que aprenda la relación parámetros → resultado, y usar ese modelo (que responde en microsegundos) para explorar.

El procedimiento, que es el mismo en toda la industria:

  1. Diseño de experimentos: elegir los puntos de simulación. En vez de una grilla (que crece exponencialmente con los parámetros), un muestreo que cubra bien el espacio: hipercubo latino.
  2. Correr las simulaciones y juntar el conjunto (parámetros → salida de interés: tensión máxima, flecha, frecuencia propia).
  3. Entrenar el modelo (regresión con regularización, red neuronal, proceso gaussiano) con validación cruzada (2.12).
  4. Medir el error sobre simulaciones que el modelo no vio. Y avisar los límites: dentro del rango de entrenamiento interpola bien; fuera de ese rango, extrapola mal.
  5. Usarlo, pero verificando los diseños finales con la simulación completa.
EjercicioCon tu ElementoBarra/Malla de codigo/PROYECTO/ (o la viga analítica de 5.2 si todavía no tenés el solver): (a) generá 200 simulaciones variando 2 o 3 parámetros con hipercubo latino; (b) entrená una regresión polinómica con ridge (2.3) y un MLP (3.4); (c) medí el error en 50 simulaciones nuevas y graficá error contra número de simulaciones de entrenamiento; (d) compará el tiempo de una simulación contra el de una predicción. Si un día tenés el solver 2D de calor, repetí con la temperatura máxima.

5.4 Mantenimiento predictivo: señales de vibración

Una máquina rotativa con un rodamiento dañado vibra distinto. Predecir la falla antes de que pase es uno de los usos más rentables de ML en la industria. El flujo clásico: medir (acelerómetro) → extraer características → clasificar (sano / falla) o detectar anomalías.

Las características típicas de una señal \(x(t)\) de \(N\) muestras: valor RMS \(\sqrt{\frac1N\sum x^2}\) (energía), curtosis (qué tan "picuda" es la señal: los golpes de un rodamiento dañado la suben), valores pico, y el espectro de frecuencias, que se calcula con la FFT (transformada rápida de Fourier). La FFT de Cooley-Tukey es además un lindo ejercicio de recursión de divide y vencerás, igual que el merge sort.

Ejercicio(a) Simulá señales: una vibración sana (senoidal de 50 Hz más ruido) y una defectuosa (la misma más impulsos periódicos que representen golpes del rodamiento). (b) Implementá la FFT recursiva (para largos potencia de 2) y verificala contra una DFT directa \(O(N^2)\). (c) Extraé RMS, curtosis y las 3 frecuencias dominantes. (d) Clasificá sano/defectuoso con tu regresión logística (2.4) y tu árbol (2.6) y medí con validación cruzada.
AutoevaluaciónSi la FFT tiene complejidad \(O(N\log N)\) y la DFT directa \(O(N^2)\), ¿cuántas veces más rápida es la FFT para \(N = 4096\), en orden de magnitud?

5.5 Series de tiempo y estimación de estado

Muchos datos de ingeniería son series de tiempo: temperatura, posición, corriente. Tres herramientas, de lo clásico a lo moderno:

  • Autorregresión (AR): predecir el valor de ahora con los \(p\) anteriores, \(x_t \approx a_1 x_{t-1} + \cdots + a_p x_{t-p}\). Los coeficientes salen de una regresión lineal (1.2). Un sistema masa-resorte-amortiguador es exactamente un AR(2).
  • Filtro de Kalman: estimar el estado real de un sistema (posición, velocidad) combinando un modelo físico con mediciones ruidosas. Es lo que usan desde un GPS hasta un robot. La versión 1D es corta y vale la pena programarla.
  • Métodos modernos de identificación de sistemas dinámicos (descomposición modal dinámica, regresión dispersa de ecuaciones) y redes recurrentes (3.9): el libro de Brunton y Kutz se centra en esta intersección entre sistemas dinámicos y ML.
Ejercicio(a) Simulá un oscilador amortiguado \(m\ddot x + c\dot x + kx = 0\) con ruido de medición, ajustá un AR(2) por mínimos cuadrados y predecí 50 pasos hacia adelante; compará con la solución exacta. (b) Programá un filtro de Kalman 1D para estimar la posición de un móvil con velocidad constante a partir de mediciones con ruido y mostrá que el error del filtro es menor que el de las mediciones crudas. (c) Estimá la vida útil restante de un sistema que se degrada exponencialmente a partir de datos hasta cierto punto.
AutoevaluaciónUn AR(2) tiene dos coeficientes. ¿Cuántos parámetros físicos (m, c, k) tiene el oscilador del que sale? ¿Por qué eso hace que el AR(2) sea una buena descripción?

5.6 ML informado por la física: PINNs

Una PINN (physics-informed neural network) es una red neuronal \(u_\theta(x)\) cuya función de pérdida no usa solo datos: también exige que la red cumpla la ecuación diferencial. Por ejemplo, para \(-u''(x) = f(x)\) en \([0,1]\) con \(u(0)=u(1)=0\), la pérdida es la suma de tres términos: el error contra los datos (si los hay), el residuo de la ecuación \((u_\theta''+f)^2\) en muchos puntos de colocación, y el error en las condiciones de borde. Las derivadas \(u_\theta'\) y \(u_\theta''\) las calcula la derivación automática (3.5, 4.5).

El trabajo original es el de Raissi, Perdikaris y Karniadakis (Journal of Computational Physics, vol. 378, 2019, pp. 686-707); una revisión posterior de los mismos autores cubre las extensiones. El libro Physics-based Deep Learning (Thuerey y colaboradores, TUM) es una introducción práctica y gratuita, con ejemplos en notebooks.

  • Ventaja: no necesita malla y puede combinar datos reales con la física; es especialmente interesante en problemas inversos (descubrir un parámetro desconocido, como una conductividad, a partir de mediciones).
  • Límite honesto: en un problema directo y bien planteado, FEM suele ser más preciso y más rápido que una PINN, y entrenar PINNs es sensible (varios términos de pérdida que compiten). No la tomes como reemplazo de FEM: tomala como una herramienta complementaria.

5.7 Optimización de diseño con modelos sustitutos y optimización topológica

Optimizar un diseño significa buscar los parámetros (dimensiones, formas) que minimizan una cosa (peso, costo) sujeto a restricciones (flecha máxima, tensión admisible). Si cada evaluación es una simulación FEM, el costo se dispara. El modelo sustituto de 5.3 lo evita: se optimiza el sustituto (barato) y se verifica el resultado con la simulación completa.

La optimización topológica va más lejos: decide dónde poner y dónde sacar material dentro de un dominio. El método clásico (SIMP) resuelve un FEM en cada iteración; la reseña que cité en 5.1 menciona usos de ML para acelerar esas iteraciones. Es un tema de investigación activa, no una receta cerrada.

Anotá cuántas evaluaciones de la "simulación cara" usó cada método.
